## Sequencing

X1 first (everything hashes or draws entropy). X2 parallel-ok with
X1 (no dependency). X3 then X4 (x509 needs every signature scheme;
curves reuse X3's bignum for the prime fields). X5 assembles the
trust story; X6 is the wire — each retires a real risk before the
next spends it. X7 is deliberately thin: one seam in `http` plus
the closeout, so the https diff stays reviewable on its own.

## Parking rules (new triggers this spec creates)

- TLS server (`tls.listen`/`accept`) — trigger: first serving
  consumer needing inbound TLS.
- TLS 1.2 fallback — trigger: first consumer hitting a 1.2-only
  endpoint.
- Session resumption / PSK — trigger: measured reconnect cost on a
  real workload.
- Client certs (mTLS) — trigger: first consumer needing mutual
  auth; brings the *signing* surface back into scope with it.
- Revocation (OCSP/CRL) — trigger: first consumer needing
  revocation proof.
- Constant-time pass — trigger: first server-side or signing
  consumer (today's client posture is documented, not claimed).
- Bundled root list — trigger: first consumer on a platform image
  with no store and no way to set the env override.

# TLS/x509 — authenticated transport — Shaping Notes

## Scope

Milestone X (x509’s letter — fresh; R was reclaimed by the descriptor
spec, T/G/E/W are taken, and L went to the LLVM lane spec, `docs/specs/2026-11-11-llvm-backend/` — spec in flight) un-parks the `crypto/tls` + `x509` row from
`docs/specs/2026-11-07-phase-2-plan/parked.md` and
`docs/specs/2026-11-06-0111-package-system/items/parked-stdlib.md`.
The trigger fired: `std/net/http`'s client is the first consumer
needing authenticated, encrypted transport beyond cleartext `net`
(`http.oxl`'s own header still reads "HTTPS stays parked (no TLS)").
The deliverable is a client-side TLS 1.3 stack plus the x509 trust
story the trigger demands — `std/net/tls`, `std/crypto/x509`, and the
crypto packages beneath them — ending in `http.get("https://…")`.

Not this spec: TLS server (`tls.listen`/`accept`), TLS 1.2 or older,
DTLS/QUIC, HTTP/2+, client certificates (mTLS), session resumption /
PSK / 0-RTT, OCSP/CRL revocation checking, certificate *issuance*
(sign/encrypt/decrypt RSA ops), a bundled root list, name-constraint
processing, an `insecure_skip_verify` flag, and any `--target js`
lane (sockets already trap under node; `tls` inherits net's path).

## Evidence

- The repo's crypto ethos is set in S4: `sha256`/`md5`/`hmac` were
  "written fresh in oxl from the public specs — no C port" and the
  item closes with "the language is sufficient." u32-in-int64
  arithmetic (`x/2**n`, `(x*2**n)&M32`) is the established pattern —
  correct first; the perf gate (X5 interop budget) is what makes it
  acceptable, not any compiler strength-reduction (there is none).
- The driver's link pattern is demand-driven off emitted text:
  `rt_sqlite_*` → `-DOXL_SQLITE` + `-lsqlite3` (or `LANG_SQLITE_SRC`
  amalgamation on Windows); `rt_sock_*` → `-DOXL_NET` + `ws2_32`;
  `rt_m_*` → `-DOXL_MATH` + `-lm`. A TLS stack that needs zero new
  link surface keeps this pattern untouched.
- `runtime/rt.c` has **no entropy source** — `rand()` seeds chan
  select, and `std/math/rand` is a documented drand48 LCG. Every
  other crypto input exists in `.oxl`; a CSPRNG cannot (it is a
  syscall), so one rt.c veneer is the minimum.
- `std/net`: `Conn{fd, st, g}` implements `io.Reader/Writer/Closer`
  with a shared close-latch — `tls.Conn` wraps it field-for-field.
  `dial_timeout` bounds connect; `rawfd()` exposes the socket for
  `set_rcvtimo`-class calls.
- `std/net/http`: `parse_url` accepts only `http://` (port 80),
  `Client{tmo}` dials `net.dial_timeout` directly — one seam to
  branch on `secure`.
- Encoding/decoding inventory already shipped: `encoding/base64`
  (PEM bodies), `encoding/hex`, `encoding/binary` (be_u16/u32 reads
  the record layer), `bytes`, `io` ifaces, `os.getenv`, `os/exec`,
  `time.unix` (CLOCK_REALTIME — cert validity checks can use it).
- CI runs ubuntu + macOS + windows (git-bash, `LANG_CC=gcc`), and
  `tests/run.sh` already gates lanes on `command -v` probes
  (gtk's `pkg-config`, amalgamation env vars; W's js lane adds `node`
  in flight) — the TLS interop lane rides the
  same probe pattern on `openssl`.
- Windows and macOS have no filesystem root bundle a stock program
  can assume; POSIX distros disagree on the path. The platform
  *does* offer stores — Windows `Cert:\LocalMachine\Root` via
  PowerShell, macOS `security find-certificate` — both reachable
  through `std/os/exec` with zero new C.

## The forks, decided

1. **Pure-.oxl crypto and protocol; rt.c contributes only entropy.**
   Options weighed:

   | option | shape | verdict |
   |---|---|---|
   | A. Fresh-from-RFC .oxl stack | all primitives + record/handshake + x509 in packages; one `rt_csrand` veneer | repo ethos; one behavior across all three CI legs; every byte reviewable; suite gates are RFC vectors + interop — but the largest .oxl surface yet and no third-party audit |
   | B. Platform TLS veneer in rt.c | OpenSSL (unix), SecureTransport or Network.framework (macOS), Schannel (Windows) behind `rt_tls_*` | audited crypto + free system roots — but ~3 divergent C backends (>1.5k lines), a deprecated-or-async-mismatched macOS API, per-platform verify semantics the suite can't pin, and the trust story *delegated*, which is what the trigger says the spec must cover |
   | C. Vendored C TLS lib | BearSSL: TLS 1.2 only — fails the floor. mbed TLS: full 1.3 but ~100k lines vendored or `LANG_TLS_SRC`-fetched | biggest dependency weight for least ownership of the answer; sqlite's system-or-amalgamation pattern exists but pulls a security-critical dep the project then can't audit |

   Option A, with the honest cost stated: the primitives are
   verify-only where possible, the wire surface is TLS 1.3 only, and
   the gates are published test vectors plus live `openssl s_server`
   interop — not self-consistency. Side-channel posture is written
   down, not waved (§Risk).

2. **TLS 1.3 only.** RFC 8446, floor and ceiling. No 1.2 negotiation,
   no downgrade path (the sentinel in ServerRandom is a hard alert),
   no renegotiation (does not exist in 1.3). Rationale: every public
   web-PKI endpoint that matters speaks 1.3; the 1.2 handshake,
   non-AEAD ciphersuites, RSA key transport, and renegotiation are
   exactly where a from-spec stack bleeds. A 1.2 fallback re-opens
   with the trigger "a consumer hits a 1.2-only endpoint."
3. **Cipher floor: two suites + one free rider.** Offer
   `TLS_AES_128_GCM_SHA256` and `TLS_CHACHA20_POLY1305_SHA256`, plus
   `TLS_AES_256_GCM_SHA384` since SHA-384 exists anyway for the
   signature set. Key shares: `x25519` and `secp256r1`; `secp384r1` is
   advertised in `supported_groups` (no share sent up front) so
   an HRR demanding it is honored (the field code exists for ECDSA
   regardless). No FFDHE, no 0-RTT, no early data.
4. **Verify-only asymmetric crypto.** Certificates need signature
   *verification* — never signing, encryption, or decryption — so the
   packages expose exactly that: `rsa` (PKCS#1 v1.5 + PSS verify),
   `nistec` (P-256/P-384 ECDH+ECDSA verify), `ed25519` (verify), `x25519`.
   A `sign`/`encrypt`/`decrypt` surface lands only with its own
   consumer (trigger: JWT/mTLS issuance or TLS server).
5. **The trust story is ours, loaded three ways.** The x509 contract
   (`items/x509-trust.md`): DER parse, chain build leaf→root by
   issuer/AKID, signature verify per the floor set, validity vs
   `time.unix`, BasicConstraints/KeyUsage/EKU checks, SAN hostname
   match. Roots resolve in order: `OXL_SSL_CERT_FILE` /
   `OXL_SSL_CERT_DIR` env (then `SSL_CERT_FILE`/`SSL_CERT_DIR` as
   fallback spellings), else the platform store — POSIX bundle paths,
   macOS `security find-certificate` exec, Windows PowerShell `Cert:`
   provider — else a named error, never silent-cleartext. No bundled
   Mozilla list: a vendored root set is a maintenance treadmill the
   release process doesn't have; the env override is the documented
   answer on stripped containers.
6. **Hostname verification: SAN-only.** dNSName SANs (wildcard on
   exactly one left-most label), iPAddress for IP literals, *no CN
   fallback* — a SAN-less cert fails `err_name` even when its CN
   matches (public CAs have issued SANs for a decade; CN matching is
   deprecated practice that hides misissuance). SHA-1/MD5 signatures
   hard-fail at parse-and-verify at every link — the one exception is
   the trust anchor's own self-signature, which is never verified
   (store membership is the trust decision), matching x509-trust.md.
7. **Expiry is hard-checked; revocation is parked.** notBefore/
   notAfter validated against wall clock — no tolerance window.
   CRL/OCSP (incl. stapling) is a documented non-goal with the same
   trigger shape as every parked row: first consumer that needs
   revocation proof. Until then `x509` says so plainly rather than
   pretending half-checks.
8. **`tls` wraps `net.Conn`; `http` gains `https` at one seam.**
   `tls.dial` = `net.dial_timeout` + `tls.client`. `tls.Conn` is
   `io.Reader/Writer/Closer` with `rawfd()` passthrough so the
   existing timeout builtins keep working. `http.Url` grows
   `secure`; `Client` grows `tlscfg: tls.Config`. No
   `insecure_skip_verify` — the `Config.verify` hook is the
   deliberate escape hatch (test fixtures and private PKI inject a
   `Roots` or a `Verifier`; a boolean that disables authentication is
   a footgun, not a feature). The hook is an iface, not a `fn` field:
   oxl's `nil` is `Ty::Err` — assignable to ifaces and slices, not to
   `fn` — so `verify: nil` must mean an empty iface, the same shape
   `http.Handler`/`hash.Hash` already set for policy injection.
9. **Hermetic gates first, interop second.** Published vectors
   (FIPS/NIST/RFC 7748/8032/5869/8439/8448) gate every primitive;
   RFC 8448's published handshake trace gates the key schedule;
   checked-in x509 fixtures (generator script in `scripts/`) gate
   the trust story; `openssl s_server` end-to-end interop runs in a
   `command -v openssl`–gated lane, never the sole gate.
10. **js-lane inherits net's answer.** Under milestone W (in
    flight): `runtime/rt-node.mjs`/`rt-browser.mjs` sockets trap21; TLS
    needs sockets, so `--target js` gains nothing here — the
    packages compile (pure .oxl) and their socket use fails the same
    documented way. A fetch-backed transport is its own trigger.

`math/rand` is named deliberately absent above — it is an LCG; its
doc comment already says so. Nothing cryptographic may consume it.

## Risk

- **From-spec correctness** is the dominant risk, not performance:
  gates are external vectors at every layer, and X6 gates on a real
  `openssl s_server` handshake where available — self-consistency
  alone is never the exit.
- **Side channels**: `.oxl` arithmetic compiles through C but offers
  no constant-time discipline (branches on secret material are
  written, not eliminated). The stack's posture is "correctness-
  verified, no constant-time claim" — recorded in `docs/tls.md` at
  closeout. A client handshake's exposure is narrow (session keys,
  not long-term identity keys), and the verify-only design means no
  signing oracle exists. A constant-time pass is parked with the
  trigger "first server-side or signing consumer."
- **Perf floor**: RSA-4096 verify < 250 ms, x25519 < 50 ms,
  handshake crypto < 1 s total on a CI leg (the dial budget is 30 s;
  crypto must not dominate it), AEAD ≥ 5 MiB/s. Gates, not
  aspirations — measured in the suite.
- **Root-store drift**: exec-based loaders depend on `security` /
  `powershell` being present (true on stock images; Nano Server-class
  minimal Windows is the exception → the env override is the
  documented answer there, and the error names it).

## The decision

**A TLS 1.3 client stack written fresh in `.oxl` from RFC 8446 +
companion RFCs, over one new rt.c entropy veneer, with the x509
trust story in `std/crypto/x509` and `https://` delivered through a
single seam in `std/net/http`.**

```oxl
// std/net/tls — public surface (v1)
struct Config {
    server_name: str,                     // verify name; dial() fills it (SNI is DNS-only)
    roots: x509.Roots,                    // empty ⇒ load_system_roots()
    alpn: []str,                          // empty ⇒ no ALPN ext
    verify: Verifier,                     // nil ⇒ default chain + hostname
}
interface Verifier {                    // override hook — an iface,
    check(leaf: x509.Cert, untrusted: []x509.Cert) -> err
}                                       // not a fn field: oxl's nil
                                        // is Ty::Err — assignable to
                                        // ifaces, never to fn
fn dial(host: str, port: int, cfg: Config) -> [Conn, err]
fn dial_timeout(host: str, port: int, tmo_ms: int, cfg: Config) -> [Conn, err]
fn client(c: net.Conn, cfg: Config) -> [Conn, err]   // wrap any net.Conn
struct Conn { inner: net.Conn, st: shared, g: int }  // io.R/W/Closer
fn (c mut Conn) read/write/close — record layer; close sends
                                   // close_notify then closes inner
fn (c ref Conn) rawfd() -> int           // passthrough for set_*timo
fn (c ref Conn) peer() -> x509.Cert      // the verified leaf
```

```oxl
// std/net/http — the seam (additions only)
struct Url { host: str, port: int, path: str, secure: int }
struct Client { tmo: int, tlscfg: tls.Config }
// parse_url: "https://" → secure=1, port 443; Client.request picks
// tls.dial_timeout vs net.dial_timeout on u.secure
```

The public surface the milestone ships, field by field. The
deliberate absences are part of the contract — they're decisions,

## `std/net/tls`

```oxl
import "std/net"
import "std/crypto/x509"

struct Config {
    server_name: str,      // verification name — dial() fills it
                           // from host verbatim. The SNI extension
                           // is sent only for DNS names, but the
                           // hostname check still runs for IP
                           // literals (against iPAddress SANs).
                           // Empty ⇒ SNI omitted AND match_hostname
                           // skipped — only legal alongside a
                           // non-nil verify, enforced at client().
    roots: x509.Roots,     // Roots{cas: nil} ⇒ load_system_roots()
                           // — lazily, only when chain verification
                           // actually runs: a non-nil `verify`
                           // replaces it, so no security/powershell
                           // exec ever fires for verify-carrying
                           // clients
    alpn: []str,           // empty ⇒ no ALPN extension
    verify: Verifier,      // nil ⇒ x509.verify + match_hostname.
                           // Non-nil ⇒ replaces BOTH (chain AND
                           // hostname) — the full-override hook for
                           // tests/private PKI/self-signed pinning.
}

interface Verifier {
    check(leaf: x509.Cert, untrusted: []x509.Cert) -> err
    // an IFACE, not a `fn` field: `nil` is `Ty::Err` in oxl —
    // assignable to ifaces, never to `fn` — so "no override" spells
    // `verify: nil`. Callers implement `check` on a small struct,
    // the same idiom as http.Handler and hash.Hash.
}

fn dial(host: str, port: int, cfg: Config) -> [Conn, err]
    // = dial_timeout(host, port, 30000, cfg) — net.dial's budget.
fn dial_timeout(host: str, port: int, tmo_ms: int, cfg: Config) ->
    [Conn, err]
    // tmo_ms bounds TCP connect; `client` then applies the same
    // budget as the handshake-flight receive timeout (a peer that
    // accepts TCP then stalls can't park the dial forever) — the
    // caller's own set_*timo applies only after the handshake
    // lands.
    // = net.dial_timeout + client(c, cfg); on handshake failure the inner
    // socket is closed before returning the err — no half-open leak.

fn default_cfg() -> Config
    // roots: Roots{cas: nil} (lazy system-store load at first
    // handshake — a store that fails to load surfaces as the
    // handshake's err, never a Config-construction surprise),
    // server_name/verify/alpn empty — the 4-field Config literal
    // is easy to get wrong; start here.

fn client(c: net.Conn, cfg: Config) -> [Conn, err]
    // handshake over an existing conn (the wrap API — proxy CONNECT
    // and tests ride this). cfg.server_name empty + cfg.verify nil
    // is err_name — a caller who means "no name check" must say so
    // with a Verifier, never by accident.

struct Conn { inner: net.Conn, st: shared, g: int, /* … */ }
    // st/g are the close latch; the elided state box carries
    // traffic keys, seq counters, and the transcript
    // st/g is the same close-latch discipline as net.Conn: copies
    // (struct value, iface box) share the cell; close wins once.

fn (c mut Conn) read(b: []byte) -> [int, err]
    // yields decrypted app-data; close_notify → io.eof();
    // post-handshake msgs (NST/KeyUpdate) are consumed inside read —
    // callers see only app-data semantics per io.Reader.
fn (c mut Conn) write(b: []byte) -> [int, err]
    // slices b into ≤16KiB records; may write short per io.Writer.
fn (c mut Conn) close() -> err
    // close_notify best-effort → inner.close(); double-close safe
    // via the latch.
fn (c ref Conn) rawfd() -> int     // inner.rawfd() — set_*timo works
fn (c ref Conn) peer() -> x509.Cert
    // the verified leaf — callers needing the presented identity
    // (audit logs, key pinning checks on top of verify) read it
    // here, never from a parallel parse.
fn (c mut Conn) asreader/aswriter/ascloser/asreadwriter  // net.Conn parity
```

**No `insecure_skip_verify`.** The flag exists in every TLS lib
and is the single most-abused TLS setting ever shipped; this
surface's answer is `verify` — a hook that says *what* trust means,
not a boolean that says "don't." Tests and private PKI pin a CA
through `roots` instead.

**Dial-time defaults:** `dial*` sets `server_name = host`
verbatim, IP literals included — the iPAddress SAN check needs it
(the SNI extension itself stays DNS-only inside `client`); ALPN comes only from `cfg.alpn` (tls doesn't guess —
`http` supplies `["http/1.1"]`).

## `std/net/http` — the seam

```oxl
struct Url { host: str, port: int, path: str, secure: int }
// parse_url: "https://" → secure=1, port 443; "http://" or bare →
// secure=0, port 80; "x://…" unsupported stays an err (unchanged).
// userinfo/query handling is untouched — this spec adds a scheme.

struct Client { tmo: int, tlscfg: tls.Config }
// NB: oxl struct literals are exhaustive — adding `tlscfg` breaks
// every `Client{tmo: N}` literal in the wild. Accepted churn
// (one-line fix per site); X7 ships a `new_client(tmo)` helper
// for callers that want the default config.
// request(): u.secure ⇒ tls.dial_timeout(u.host, u.port, cl.tmo,
// cl.tlscfg) — cfg.server_name defaulted to u.host when
// empty, cfg.alpn defaulted to ["http/1.1"] when empty;
// else ⇒ net.dial_timeout (unchanged path).
```

`serve` is untouched — TLS server is a parked trigger, not a stage.
`Roots`/`Config` are by-value params carrying `own` fields — fine
under scope arenas (no aliasing escapes the call), stated so the
by-value shape isn't read as a borrow contract.
The `host:` header appends `:port` only when the port differs
from the scheme default (443 secure, 80 else) — no spurious
`:443`. `connection: close`, read-until-EOF body loop,
and `Resp` shape all carry over byte-for-byte, with one deliberate
divergence: a TLS peer that closes TCP without `close_notify`
surfaces `err_eof` — fail-loud on truncation where permissive
HTTP/1.1 handling would have returned the partial body. From
`request`'s
view a `tls.Conn` is just the `io` plumbing `net.Conn` already was.

## Error taxonomy (what callers see)

`dial`/`client` surface failures in three layers, all `err`:

| layer | examples | caller meaning |
|---|---|---|
| transport | net dial errors verbatim | host unreachable, refused |
| protocol | `err_proto`, `err_alert` (alert name in text), `err_eof` | peer not TLS, mid-handshake cut |
| trust | `err_sig` `err_expired` `err_notyet` `err_ca` `err_eku` `err_path` `err_root` `err_name` `err_alg` `err_der` `err_roots` | the x509 verdict — `errors.is` categories, actionable ("add the CA to OXL_SSL_CERT_FILE", "clock is wrong") |

Trust errors are never flattened into "handshake failed" — the
name/dates/verdict belong in the error text so a failed `https.get`
tells the user *which* check lost.

# items/tls13-wire.md — TLS 1.3 record, handshake, and key schedule contract

X6's deliverable. Everything on the wire is RFC 8446; this file pins
the subset offered, the message flow implemented, the key schedule
derivation, and the alert/error semantics — the parts a from-spec
implementation must not improvise.

## Offered parameters (ClientHello)

| field | value |
|---|---|
| `random` | 32 bytes fresh `rt_csrand` — per ClientHello; the downgrade-sentinel surface on the ServerHello side |
| `legacy_version` | 0x0303 (TLS 1.2 encoding position; 1.3 rides `supported_versions`) |
| `legacy_session_id` | 32 bytes of fresh `rt_csrand` — compat mode §4.1.2; the ServerHello must echo it verbatim (`legacy_session_id_echo` check, `illegal_parameter` else — §4.1.3) |
| `legacy_compression_methods` | single `0x00` (null) — required field, always this value |
| `supported_versions` | 0x0304 only |
| `cipher_suites` | `TLS_AES_128_GCM_SHA256` (0x1301), `TLS_CHACHA20_POLY1305_SHA256` (0x1303), `TLS_AES_256_GCM_SHA384` (0x1302) — in that order |
| `supported_groups` | `x25519` (0x001d), `secp256r1` (0x0017), `secp384r1` (0x0018) — all three advertised; a server may only pick an advertised group |
| `key_share` | shares for x25519 and secp256r1 (two shares dodge the common HRR) |
| `signature_algorithms` | `ecdsa_secp256r1_sha256` (0x0403), `ecdsa_secp384r1_sha384` (0x0503), `ed25519` (0x0807), `rsa_pss_rsae_sha256/384/512` (0x0804/0x0805/0x0806), `rsa_pkcs1_sha256/384/512` (0x0401/0x0501/0x0601) |
| `server_name` | the DNS name being dialed; omitted for IP literals |
| `alpn` | from `Config.alpn`; absent when empty |
| `psk_key_exchange_modes` | `psk_dhe_ke` — sent for form (we offer no PSKs); keeps the CH shape boringly standard |

Compatibility mode: a dummy ChangeCipherSpec is sent and CCS
records from the server are tolerated mid-flight (RFC 8446 §D.4
middlebox accommodation).

**Downgrade sentinels:** the last 8 bytes of ServerHello.random
equal to either RFC 8446 §4.1.3 sentinel is a hard `illegal_parameter`
alert — we offer 1.3 only, so their presence is an attack, not a
negotiation.

RSA-PSS in CertificateVerify: `salt_len` pins to the hash length
(the generic "salt-len recover" verify path accepts anything — we
send and accept only hashlen).

## Handshake state machine

```
ClientHello
  → [HelloRetryRequest — at most once; echo any `cookie`
     extension verbatim (§4.2.2), rebuild CH with a key_share for
     the demanded group if it's x25519/secp256r1/secp384r1
     (`illegal_parameter` alert else); transcript carries the HRR
     message_hash; ClientHello#2 reuses the SAME
     legacy_session_id as #1. A second HRR → `unexpected_message` alert]
  → ServerHello        — must carry `supported_versions`=0x0304
                          (its mandatory pin; a 0x0303-only ServerHello
                          is a 1.2 answer → `protocol_version` alert).
                          Suite echo must ∈ offered; the
                          selected group must be one whose
                          key_share we actually sent (post-HRR:
                          the HRR-demanded group — a group merely
                          listed in supported_groups carries no
                          ECDHE secret); any extension we didn't
                          offer → illegal_parameter; else alert.
                          The peer's key_share validates BEFORE use:
                          x25519 → RFC 7748 all-zero output check
                          (`illegal_parameter` alert — the RFC's
                          "MUST abort"); P-256/P-384 →
                          point-on-curve check (invalid-curve defense)
  → EncryptedExtensions — ALPN echo must ∈ offered list when sent;
                          any unoffered extension →
                          illegal_parameter
  → [CertificateRequest mid-flight — answered with an empty
     Certificate message (certificate_list len 0, §4.4.2.4 —
     the RFC-mandated answer; a server requiring client auth
     then alerts `certificate_required`) placed immediately
     before our CertificateVerify/Finished flight, echoing the
     request's certificate_request_context verbatim. mTLS
     itself stays out of scope.]
  → Certificate         — each cert_parse'd; leaf + untrusted chain;
                          per-entry extensions (OCSP staples, SCTs)
                          parsed over, ignored
  → CertificateVerify   — signature over the running transcript;
                          signed content is 0x20×64 +
                          "TLS 1.3, server CertificateVerify" + 0x00
                          + transcript (§4.4.3); alg must ∈
                          signature_algorithms and be a CV-legal
                          alg (see below) — else alert. A local
                          verify/chain failure answers with an
                          alert — CertificateVerify *signature*
                          failure → decrypt_error (§4.4.3);
                          chain-signature/parse → bad_certificate;
                          validity → certificate_expired — not a
                          bare close
  → Finished            — verify_data == HMAC(finished_key, transcript)
  → [client Finished]   — handshake complete; app traffic keys live
```

CertificateVerify accepts `rsa_pss_rsae_*`, `ecdsa_*`, `ed25519`
only — `rsa_pkcs1_*` values are advertised (cert *signatures* need
them: roots still issue PKCS#1 v1.5) but are illegal in CV per RFC
8446 §4.4.3 and rejected there. The x509 chain itself may carry
PKCS#1 signatures — `x509.verify` accepts them.

Post-handshake, consume quietly:
- **NewSessionTicket** — parsed and dropped (resumption is out of
  scope; erroring on it would break interop with every server that
  sends it).
- **KeyUpdate** — `update_requested` → apply peer keys and answer
  `update_not_requested`; `update_not_requested` → apply only.
  Never initiated by us — a sent KeyUpdate rotates the SENDER's
  traffic secret, so our send keys never rotate in v1.
- CertificateRequest post-handshake — protocol-illegal here
  (`post_handshake_auth` is never offered), so the strict read is
  `unexpected_message`. We answer leniently instead — the same
  empty Certificate as mid-flight — because real servers do send
  it and an alert buys nothing: the server's own follow-up
  (usually `certificate_required`) ends the session either way.
  The strict alternative is recorded, not chosen. Any other
  handshake-type post-handshake → `unexpected_message` alert.

## Key schedule

Standard RFC 8446 §7.1 chain, all through `expand_label` — `std/net/tls`'s TLS-shaped variant ("tls13 " prefix; plan.md pins the residence):

```
early secret   = extract(0, zeros)
handshake sec  = extract(der(early), ecdhe_shared)
  → c_hs_traffic / s_hs_traffic  (keys+iv for handshake flight —
     labels "c hs traffic"/"s hs traffic", transcript scoped
     CH..ServerHello)
master secret  = extract(der(handshake), zeros)
  → c_ap_traffic / s_ap_traffic  (keys+iv for app data — labels
     "c ap traffic"/"s ap traffic", transcript scoped
     CH..server Finished)
```

with `finished_key = expand_label(hs_traffic, "finished", "", hlen)`
and `verify_data = HMAC(finished_key, transcript_hash)`. Transcript
is the running hash over raw handshake-message bytes (incl. the
HRR `message_hash` substitution per §4.4.1). Hash follows the
negotiated suite: SHA-256 for 0x1301/0x1303, SHA-384 for 0x1302.

**Test anchor:** RFC 8448 §3's published trace — the fixture feeds
the published server flight and published ECDHE secret; the
implementation must derive the published `c/s_hs_traffic` and
`c/s_ap_traffic` keys byte-for-byte. This is the gate that proves
the whole HKDF chain against an external answer.

## Record layer

- `TLSCiphertext`: 5-byte header `{type=23, version=0x0303, len}`;
  fragment ≤ 16384 + 256 expansion — larger inbound →
  `record_overflow` alert.
- AEAD-open failure → `bad_record_mac` alert (never a bare
  close — the record layer's only integrity verdict).
- Handshake messages reassemble across record boundaries and
  coalesce within one record — a Certificate flight routinely
  exceeds one fragment, and several handshake messages may share
  one. The handshake reader buffers until each message's 4-byte
  header length is complete — never assume record == message.
  The buffer is bounded: pending handshake bytes cap at 256 KiB
  before a flight completes — a peer streaming fragments without
  finishing trips `record_overflow` (pre-auth memory stays
  flat).
- Nonce: `iv ^ (seq` zero-padded to iv len`)`; seq per direction,
  never reused, reset at each secret epoch; wrap → `err_proto`
  (a seq can never legally wrap in our lifetime anyway).
- AAD: the 5-byte header verbatim.
- Inner plaintext: `content || type || zeros` — strip trailing
  zeros, last nonzero byte is the real type; all-zero content →
  `unexpected_message`.
- Outbound padding: none (we send `content||type` only — padding
  is optional and traffic analysis is documented in the risk
  section).
- Record content types: CCS 20, alert 21, handshake 22,
  application_data 23. Inbound CCS is tolerated *once* per
  direction (middlebox compat per §D.4 — more than one is
  `unexpected_message`); alert records map to `err_alert` with
  the alert name; any other unknown type is `unexpected_message`.

## Errors / alerts

- Orderly close (close_notify received) → `read` yields
  `io.eof()`; `close()` sends close_notify best-effort then
  closes `inner` (a wedged peer can't hold the fd).
- TCP EOF mid-record or without close_notify → `err_eof`
  (distinguished from orderly: truncation is never silent).
- Any alert received → `err_alert` carrying the alert name in
  message text (`bad_record_mac`, `certificate_unknown`, …) —
  debugging a failed handshake demands the server's complaint.
- Local verification failures surface the x509 category (`err_sig`,
  `err_expired`, `err_root`, `err_name`, …) — `tls.dial` callers
  get the *reason*, not a flattened "handshake failed".
- Handshake shape violations → the matching alert sent, then
  `err_proto`.

# items/x509-trust.md — the x509 trust contract

X5's deliverable and the reason the trigger exists: the roadmap says
the spec "must cover the x509 trust story, not just a wrapping API."
This file is that story, pinned end to end — parse, path build,
verify, roots, hostname, expiry, and the revocation stance.

## Package surface

```oxl
package x509    // std/crypto/x509

struct Cert {                       // a parsed certificate; fields
    raw: own []byte,                //  are populated lazily at parse —
    version: int, serial: own []byte,
    issuer: str, subject: str,      //  RDN → printable form — display
    //  only; path linking compares DER, never these strings
    issuer_der: own []byte, subject_der: own []byte,
    //  the raw Name encodings — OWNED copies (not slices into
    //  `raw`; the cert may outlive its parse buffer). Every `str`/
    //  `[]str` field above carries the same owned-backing rule —
    //  contents copied out at parse, never views into `raw`
    not_before: int, not_after: int,//  epoch seconds (UTCTime/GenTime)
    dns_names: own []str,           //  SAN dNSName entries, lowercased
    ip_addrs: own []str,            //  SAN iPAddress entries —
                                   //  v4 dotted quad, v6 RFC 5952
                                   //  canonical (lowercase, ::);
                                   //  match_hostname normalizes the
                                   //  URL's `[v6]` literal to the
                                   //  same form before comparing
    is_ca: int,                     //  BasicConstraints cA
    max_path: int,                  //  pathLenConstraint, -1 = unset
    ku: int,                        //  KeyUsage bitmask, -1 = absent
    eku: own []str,                 //  EKU OID strings, empty = absent
    sig_alg: int,                   //  signatureAlgorithm (enum below)
    spki_alg: int,                  //  subjectPublicKeyInfo alg
    spki: own []byte,               //  the raw SPKI (verify input)
    skid: own []byte, akid: own []byte,
    sig: own []byte, tbs: own []byte,
}
struct Roots { cas: own []Cert }

fn parse_cert(der: []byte) -> [Cert, err]
fn parse_pem(text: str) -> [own []Cert, err]     // every CERTIFICATE block
fn (r mut Roots) load_pem(text: str) -> [int, err] // count appended
fn (r mut Roots) append(c: Cert)
fn load_system_roots() -> [Roots, err]
fn verify(leaf: Cert, untrusted: []Cert, roots: Roots,
          name: str, at: int) -> [own []Cert, err]   // returns the path
          // name non-empty ⇒ match_hostname runs inside verify
          // after the path verifies; name "" skips it (the
          // Config.verify escape hatch decides its own policy)
fn match_hostname(c: Cert, name: str) -> err
          // exported separately so a custom Verifier can reuse
          // exactly this rule
```

`SIG_*` consts: `rsa_pkcs1_sha256|384|512`, `rsa_pss_sha256|384|512`,
`ecdsa_p256_sha256`, `ecdsa_p384_sha384`, `ed25519` — the acceptance
set, and it's a *set*: anything else (sha1, md5, sha224, unknown
OID) yields `err_alg` at verify. `SPKI_*`: `rsa`, `ec_p256`,
`ec_p384`, `ed25519`.

## DER / PEM

- Reader is definite-length only (DER and the cert form of BER both
  are), TLV-walking; indefinite form is `err_der`. Tags consumed:
  SEQUENCE, SET, INTEGER (positive only — leading-zero stripped),
  BIT STRING (unused-bits byte must be 0), OCTET STRING, NULL, OID,
  PrintableString, UTF8String, IA5String, BMPString (decoded for
  display only — never matched), UTCTime, GeneralizedTime, explicit
  context tags `[0]`/`[3]` per RFC 5280. String tags outside that
  set (T61String/TeletexString and friends — live in older real-world
  certs) are skipped, not `err_der`: issuer/subject strings are
  display-only, DER bytes are what's matched. UTCTime's 2-digit
  year follows RFC 5280: YY < 50 ⇒ 20YY, else 19YY.
- Rejects, all `err_der`: length over remaining bytes, 64-bit
  overflow lengths, negative INTEGERs, non-minimal length encodings
  (long form where short suffices), trailing garbage after the top
  SEQUENCE.
- PEM is `-----BEGIN CERTIFICATE-----` blocks → block framing
  strips the 64-col line wrapping, then `encoding/base64.decode`
  (strict alphabet + %4 padding — decode never sees the newlines);
  non-certificate blocks are skipped, so a mixed bundle file parses
  clean.
- `Cert` keeps `tbs` verbatim — signature verification covers the
  raw TBSCertificate bytes exactly as transmitted, never a re-encode.

## Path building and verification

`verify` builds a path leaf→root and checks it:

1. **Build.** Candidate issuers: `untrusted` intermediates (the
   server's Certificate flight) then `roots`. Link rule:
   `child.issuer_der` byte-equals `candidate.subject_der`
   (DER byte-equal — the printable forms are display-only), tightened to
   `akid`==`skid` when both present. Loops cap at 8 links —
   `err_path` beyond. First path that verifies wins; alternatives
   are tried (cross-signed roots).
2. **Per-cert checks, every link.** `at` inside
   `[not_before, not_after]` → `err_expired` / `err_notyet`.
   `sig_alg` ∈ acceptance set → else `err_alg` (SHA-1/MD5 are
   rejected *here*, not by omission — a chain containing one dies
   the same way whether it's leaf, intermediate, or a root that
   signed anything). Signature over `tbs` verifies under the
   issuer's SPKI → else `err_sig`. Verification is *real* — RSA
   v1.5/PSS, ECDSA P-256/P-384, Ed25519 — through X3/X4.
3. **CA checks on every issuer link.** `is_ca` → else
   `err_ca`. `ku` present → must carry keyCertSign. `max_path` ≥
   subordinate-CA count below it → else `err_path`. An
   intermediate carrying EKU that contains neither serverAuth
   nor anyEKU fails `err_eku` — an EKU-restricted CA can't
   vouch usages it isn't authorized for.
4. **Leaf checks.** EKU absent, anyEKU, or containing
   serverAuth → pass; otherwise `err_eku`. `ku` present → must
   carry digitalSignature (TLS 1.3 auth is always a signature).
5. **Trust anchor.** The terminal issuer must be a `roots` member
   (`raw`-equal) → else `err_root`. Anchors are trusted by store
   membership, so the anchor's own self-signature is never verified
   and the sig-alg check (step 2's SHA-1/MD5 hard-fail) does not
   reach it — a SHA-1 self-signed anchor in the store validates,
   matching real trust stores. The returned path includes the
   anchor.

NameConstraints is not processed — parked with the
revocation/name-constraint trigger. One floor rule: the
processed critical set is {basicConstraints, keyUsage,
extKeyUsage, SAN, SKID, AKID} — any *critical* extension outside
it fails `err_der` (a critical nameConstraints we can't honor
must not validate as an ordinary root); a non-critical
nameConstraints is ignored per RFC 5280. Deliberate divergence
from a full PKIX stack, documented in docs/tls.md.

`untrusted` is treated as attacker-controlled throughout: it may
omit intermediates (chain fails `err_root`), reorder (harmless —
the build is by name), or append junk (skipped). A path built only
from untrusted certs with no roots link fails — the store is the
only source of trust.

## Trust roots: resolution order

`load_system_roots()` walks this list, first non-empty wins:

1. **`OXL_SSL_CERT_FILE`** — a PEM bundle file (any `*.pem`-
   readable concatenation). `OXL_SSL_CERT_DIR` — a directory
   scanned for `*.pem`/`*.crt`/`*.cer` files, each loaded
   wholesale (this is *not* openssl's hashed-capath layout —
   documented in docs/tls.md). Either set to a bad path →
   `err_roots` naming the var — an override that doesn't work
   must not fall through silently to the store it meant to
   replace.
2. **`SSL_CERT_FILE` / `SSL_CERT_DIR`** — same semantics;
   honored so tools configured for the OpenSSL convention work
   unmodified.
3. **Platform store:**
   - Linux/Unix: first existing of
     `/etc/ssl/certs/ca-certificates.crt` (Debian/Ubuntu),
     `/etc/pki/tls/certs/ca-bundle.crt` (Fedora/RHEL),
     `/etc/ssl/ca-bundle.pem` (openSUSE),
     `/etc/pki/ca-trust/extracted/pem/tls-ca-bundle.pem`,
     `/etc/ssl/cert.pem` (Alpine, macOS, *BSD).
   - macOS: if no file matched, exec
     `security find-certificate -a -p
     /System/Library/Keychains/SystemRootCertificates.keychain`
     (explicit keychain path — the bare invocation reads the
     user's keychains, not the System Roots store) via `os/exec` and parse the PEM output — live
     store, no framework link needed.
   - Windows: exec `powershell.exe -NoProfile -Command`
     emitting each `Cert:\LocalMachine\Root` and
     `Cert:\CurrentUser\Root` cert's `RawData` base64'd — parse
     the PEM-shaped output. One exec at first use per process,
     cached in the returned `Roots`.
4. **Fail:** no source yields ≥1 root → `err_roots` naming
   `OXL_SSL_CERT_FILE` as the override — never a silent empty
   pool (an empty pool would make every chain `err_root` with a
   misleading smell).

`cas` nil (vs a non-nil-but-empty `cas`, which is a deliberate
pin to *zero* anchors — everything verifies `err_root`) ⇒
`Config.roots` empty ⇒ `client` calls `load_system_roots()` once
per handshake (cheap on POSIX; the exec paths amortize to one
spawn — callers that care hold a `Roots` and reuse it). A
non-empty `roots` short-circuits all of the above — that's the
pinning path: `roots.load_pem(myca)` + empty env gives exactly
one trust anchor.

## Hostname verification (`match_hostname`)

- `name` empty → `err_name` — a caller that means "don't check"
  uses `Config.verify`, never an empty name (the check on empty
  is what makes the skip legible rather than accidental).
- IP literal (v4 dotted quad or `[v6]`) → matches `ip_addrs`
  exactly; never dns_names.
- DNS name → lowercase-compare against `dns_names`. Wildcard
  `*.example.com` matches exactly one left-most label
  (`a.example.com` yes; `example.com`, `a.b.example.com`,
  `xample.com` no). `*` elsewhere or mid-label is literal, not
  wild.
- **No CN fallback.** A cert with zero `dns_names`+`ip_addrs`
  fails `err_name` for any name — subject CN is read for
  display only. This matches current browser practice and is the
  decision the spec owns, stated so a later "compatibility" ask
  has to argue *for* CN, not discover its absence.

## Expiry and time

`at` is an explicit epoch parameter — `verify` takes it (tests
pin it; `tls` passes `time.unix()`). Not-before and not-after are
inclusive bounds; both fail closed. There is no skew tolerance —
a validation library can't negotiate the user's clock, and a
fudged window hides real expiry.

## Revocation stance

v1 performs **no** revocation checking: no CRL fetch, no OCSP,
no stapled-status evaluation, no must-staple enforcement. That is
a documented limitation (`docs/tls.md` names it), not an
oversight — the trigger text asks for the trust story to be
specified, and honesty here is part of it. Reopen trigger:
first consumer needing revocation proof; the `verify` hook means
a caller can layer its own check today without a std change.

## Errors

`err_der`, `err_alg`, `err_sig`, `err_expired`, `err_notyet`,
`err_ca`, `err_eku`, `err_path`, `err_root`, `err_name`,
`err_roots` — package-level sentinel `err` values. Detail text
(cert subject, offending name) is the message and the sentinel
rides as the cause — `errors.wrap(detail, sentinel)`.
`errors.new` interns by message text, so wrapping is
what keeps `errors.is(e, err_expired)` matching when the message
carries the cert's name. Callers branch on category, never on
message text.
