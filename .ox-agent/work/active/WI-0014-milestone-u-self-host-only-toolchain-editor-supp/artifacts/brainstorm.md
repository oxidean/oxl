# WI-0014 brainstorm — milestone U: self-host-only toolchain + editor support

Context: oxl ships two drivers — the Rust seed (`oxl/`, ~25k LOC,
bootstrap input only per ADR-0006) and the self-hosted product driver
(`cmd/oxl/*.oxl`, what releases actually ship — release.yml copies
`target/oxl-self` into the toolchain asset). The seed exists solely to
emit gen-1 C for the fixpoint gate in `tests/run.sh`. Dropping it
removes the last non-oxl compiler surface. In parallel, `oxl lsp`
exists but advertises only diagnostics/hover/definition, and no
editor integration ships anywhere. These are the forks inside that
shape.

## Fork U-a — stage-0 source after the Rust drop

The fixpoint needs *a* seed binary that can compile `bootstrap/` +
`cmd/oxl` to C. Options for where it comes from:

| option | shape | tradeoff |
|---|---|---|
| **A. Checked-in C snapshot** | `bootstrap/stage0/oxl.c` (~1.6 MB, verified: compiles with `cc` + `runtime/rt.c` alone) committed; CI does `cc stage0.c rt.c -o oxl-seed`; run.sh uses it as SEEDOXL | deterministic, offline, one artifact for all 3 CI OSes; freshness is *enforced twice* — run.sh diffs the seed emit against the checked-in snapshot byte-for-byte (stale → regenerate) and the gen1/gen2 fixpoint still gates emit drift; regeneration needs a working oxl (installed release toolchain), documented as `scripts/stage0.sh` |
| B. Fetch previous release | CI downloads the pinned prior tag's toolchain asset as seed | no generated file in repo; but adds a network dep + version pin to every CI/release run, per-OS asset selection, and a bootstrap deadlock window if release assets change shape |
| C. Frozen minimal Rust seed | strip `oxl/` to just enough emit | keeps Rust in the tree — the thing being removed; two compiler surfaces forever |

Recommendation: **A**. The snapshot is a build artifact treated like
a lockfile — regenerated by script, verified by the fixpoint it
feeds. Go/Rust stage0 playbooks both land here eventually; starting
with the checked-in snapshot makes the dependency explicit and the
CI hermetic.

## Fork U-b — snapshot regeneration contract

| option | shape | tradeoff |
|---|---|---|
| **A. Regen on demand + CI gate** | `scripts/stage0.sh` rebuilds `bootstrap/stage0/oxl.c` from current sources via an installed oxl; the fixpoint fails loudly when it is stale | zero ceremony per PR; staleness surfaces exactly when it matters (emit drift) |
| B. Regen every compiler-touching PR | mandate snapshot refresh in the same PR | churn on every codegen change; easy to forget, gate catches it anyway |

Recommendation: **A** — the fixpoint *is* the freshness check;
document the regen command in CONTRIBUTING and the failure message.

## Fork U-c — LSP JSON layer

`cmd/oxl/lsp.oxl` hand-rolls `json_str`/`json_num`/`extract_id`/
`json_escape` — first-hit substring extraction that cannot express
nested params, arrays, or escaping edge cases. Completion items,
semantic-token arrays, and workspace edits all exceed it.

| option | shape | tradeoff |
|---|---|---|
| **A. `std/encoding/json`** | the package exists (`std/encoding/json/`); port lsp.oxl's wire I/O onto a real parse → typed value → serialize path | correct by construction; needs the package's API verified against LSP payload shapes (it was written for data exchange, not a hot stdio loop — check alloc behavior) |
| B. Extend the naive extractors | add `json_arr`/`json_obj` substring walkers | keeps zero-dep shape; every new payload type reinvents parsing; escape handling stays hand-rolled and wrong-prone |

Recommendation: **A** — verify `std/encoding/json` round-trips the
LSP method set in a probe test first; if its DOM is too heavy for
per-keystroke completion, scope a minimal `lsp/json.oxl` reader
inside `cmd/oxl/` instead. Decide at U2 kickoff with a measured
probe, not up front.

## Fork U-d — LSP capability set

Current: `textDocumentSync:1` (full), publishDiagnostics,
hover, definition. The daily-driver set, mapped to what the checker
already indexes (`check.UseRec` — file/span/sig/def span — plus
`Ck.declsv`/`DeclEnt` and the fn/struct/enum/global tables):

| capability | data source | feasibility |
|---|---|---|
| completion | `Ck` decl tables + scope chain + keywords + std surface | medium — needs scope-aware candidate ranking; v1 = prefix match over in-scope decls + keywords |
| signatureHelp | `FnSig` at enclosing call paren via UseRec/spans | medium — active-param index from arg commas |
| documentSymbol | `declsv` spans → tree by containment | easy — flat list, nest by span |
| formatting | `oxl fmt` pipeline (fmt.oxl, 3.8k LOC) | easy-medium — needs a lib entry (`fmt_text(src)->str`) factored out of `cmd_fmt`; range formatting parked |
| semanticTokens | lexer token stream + UseRec symbol kinds → legend | medium — the highlighting answer for LSP clients; legend fixed at initialize |
| references | all UseRecs sharing a def span | easy — index already records both ends |
| rename | references edits + def edit, per-file text edits | medium — needs WorkspaceEdit payload + conflict checks (shadowed locals) |
| documentHighlight | UseRecs at same def | easy — subset of references |
| didChangeWatchedFiles / workspace | per-dir re-analysis invalidation | medium — current model re-analyzes the doc's package dir; add file-watch → invalidate `Anl` keys |

Recommendation: all of the above except callHierarchy/inlayHint/
codeAction (parked — no data source worth the surface). Order by
dependency, not alphabet: JSON layer → completion/signature →
symbols/formatting → semanticTokens → references/rename/highlight →
watched-files.

## Fork U-e — semantic token classification

| option | shape | tradeoff |
|---|---|---|
| **A. Lexer kinds + UseRec resolution** | tokenify via the same lexer the parser uses; classify keywords/types/strings/comments from token kind; identifiers upgraded via UseRec def kind (fn/struct/enum/field/var) | checker-accurate; needs a lexer entry that exposes token spans — verify `lexlib`/`parser` surface exposes one, else add a thin tokenize fn |
| B. TextMate-grammar-driven | reuse `oxl.tmLanguage.json` scopes | drifts from real grammar; duplicates the grammar in a second engine — rejected |

Recommendation: **A** — semantic tokens are *the* language-correct
highlighting; the tmLanguage grammar (U-f) covers non-LSP surfaces.

## Fork U-f — highlighting surfaces

Three consumers, one artifact:

- **`editors/grammars/oxl.tmLanguage.json`** authored in this repo —
  the TextMate grammar. Consumers: the VS Code extension (below),
  editors with tmLanguage support, and — vendored — oxidean-app's
  Shiki blob highlighting (same lane as `tsrx`/`ripple`: copy into
  `apps/web/src/lib/grammars/`, register in `highlight.ts`
  `CUSTOM_LANG_INPUTS`, add the `oxl` row to
  `crates/oxidean-core/src/languages.rs` + regen api-client — a
  **separate oxidean-app PR**, tracked as a follow-up item).
- **VS Code extension** in `editors/vscode/` — minimal: language
  configuration (comments, brackets), `oxl.tmLanguage.json` as the
  syntax, launch config for `oxl lsp`, README install snippet. No
  build step, no marketplace publish in this milestone.
- **Neovim** — `docs/editors.md` with the lspconfig snippet
  (`cmd = {"oxl","lsp"}`); treesitter grammar is a separate
  ecosystem artifact, parked with a trigger (someone upstreaming it).

## Fork U-g — LSP workspace model depth

| option | shape | tradeoff |
|---|---|---|
| **A. Single-root, package-dir analysis** | keep the current model — analyze the package dir containing the doc (loader already resolves imports transitively); add watched-file invalidation | matches how oxl projects are laid out (`oxl.mod` root); no workspace-folders protocol surface |
| B. Full workspace folders | `workspaceFolders`, cross-root resolution, per-root `oxl.mod` discovery | real multi-root semantics — but oxl.mod already defines the project root; multi-root adds protocol surface for a case the module system doesn't model |

Recommendation: **A** — `oxl.mod` *is* the workspace boundary;
`rootUri` honored as the analysis root, `workspaceFolders`
accepted-but-single. Park true multi-root behind a trigger.

## Fork U-h — Rust removal blast radius

What `oxl/` actually feeds today: ci.yml `cargo build` + run.sh
SEEDOXL, release.yml same + toolchain asset assembly, dependabot
cargo ecosystem, CONTRIBUTING/README Rust mentions, ISSUE_TEMPLATE
bug_report (probably asks for rust version — check),
`.ox-agent/config.yaml` reference. `prototype/` is unrelated C
experiments — stays.

| option | shape | tradeoff |
|---|---|---|
| **A. Full removal in U1** | delete `oxl/`, swap CI/release to snapshot-seed, update all references in the same PR | one atomic milestone; big diff but mechanical; no half-state where two bootstrap paths coexist |
| B. Keep `oxl/` frozen one release | land LSP/editor first, drop Rust in a follow-up | defers the risk; but the milestone was scoped as one unit and the snapshot path is already proven |

Recommendation: **A** — the user asked for the whole milestone in
one PR; U1 lands first within it so every later stage builds on the
final toolchain shape.

## Resolved without fork

- `oxl fmt` already exists in the self-hosted driver — formatting is
  exposure, not new machinery.
- `std/encoding/json` exists — the JSON question is adoption, not
  authoring.
- Semantic tokens vs grammar: both, different surfaces (LSP clients
  get checker-accurate tokens; web/forge gets the tmLanguage).
- Rename conflicts: v1 rejects rename when the target name would
  capture a different binding (shadow check via UseRec def spans);
  full scope-aware capture analysis parked.
- No AI-attribution, SemVer commit grammar, and the merge bar all
  apply unchanged.
